# 踢球报名小程序

解决微信群约球的三个问题：报名信息被闲聊淹没、不知道人数够不够开踢、报名后不告而别没人知道。
本产品以「球局」为单位，提供发起、报名、定位到场、实时人数与信誉结算的完整闭环：一句话，**只要点了取消就不算鸽；报名了不吭声直接消失，才算鸽。**

当前进度：**第三阶段 —— 全部 8 个页面 + 两张地图 + 视觉统一已完成，本地已全部验证；后端已迁移到 uniCloud 免费服务空间方案（代码完成、测试全过，待开通空间部署）**。仍不依赖真实 AppID 和云空间：小程序默认走本地 mock 层（`store.js` 的 `BACKEND='mock'`），可完整演示发起、报名、签到、结算口径、申诉裁决与通知落地；等开通 uniCloud 免费空间后按文末「需要用户配合的事项清单（uniCloud 版）」照单操作即可切换上线。

> **后端路线变更（重要）**：原定的微信云开发**不是长期免费的**（新用户体验期后个人版 19.9 元/月起），经用户决定改走免费方案：**uniCloud 支付宝云免费服务空间**（云函数 URL 化 HTTPS + 自建会话鉴权）。微信云开发版代码保留在 `cloudfunctions/` 与 `database/` 里，只读、已弃用，不再维护；现行后端全部在 `uniCloud/`，迁移细节见下文「后端迁移：uniCloud 免费方案（现行）」。

## 技术路线

- 微信原生小程序（WXML / WXSS / JS），无框架、无 npm 依赖
- 后端为 **uniCloud 免费服务空间（支付宝云）**：一个 `api` 云函数三用（URL 化 HTTPS 业务接口 + 每小时定时结算 + 读时惰性结算）+ 云数据库 8 集合；登录走自建会话 token（URL 化接口没有微信云函数的上下文 OPENID）。`utils/store.js` 有 `BACKEND` 开关（`'mock'` 默认 / `'unicloud'`），两种模式方法名与出入参结构一致，页面层零改动
- ~~微信云开发后端（`cloudfunctions/`）为历史方案，已弃用，只读保留~~
- 规则引擎 `utils/rules.js` 为纯函数，不依赖 `wx` API，可直接在 Node 里单测

## 定版规则速查

| 规则 | 定版口径 |
|---|---|
| 球局合并 | 同一球场（地点相同或距离 ≤500 米，haversine 计算）且与**原局**开球时间相差 ≤2 小时 → 合并；只与原局比，防连环合并；率先发起者为唯一发起人，后来者转普通报名人 |
| 人数与赛制 | 报名/到场**不设上限、无候补**；赛制只是每队人数（5/8/11/自定义），成局门槛 = 每队人数 × 2 |
| 接波组队 | 按到场签到顺序组队，先到先踢；满员前两队在踢、其余满员队等候、未满队组队中（如 5 人制到场 17 人 = 3 队满 + 第 4 队 2/5） |
| 报名状态 | 确定报名（计成局、担鸽责）/ 观望（不计成局、不担鸽责）/ 已取消 / 已到场 / 已结算 |
| 鸽的判定 | 确定报名 + 结算前未取消 + 从未签到 = 鸽 +1；**结算前任意时间取消免鸽** |
| 结算时刻 | 开球时间 + 4 小时；发起人提前结束不提前结算；发起人取消整场则全员免鸽 |
| 鸽王等级 | 按有效鸽次数：1 一级鸽王 / 2–3 二级鸽王 / 4–6 三级鸽王 / 7+ 鸽帝；有效鸽 = 历史鸽 − 已抵消 − 已撤销 |
| 抵消（赎鸽） | 连续守约（确定报名且签到）满 5 场抵消最早 1 次，进度清零重攒；中途再鸽进度清零；空降到场只计总出席、不计抵消进度 |
| 签到 | 球场为中心默认半径 500 米围栏；开球前 1 小时开启，结算时刻关闭；围栏内打开小程序即签到，仅取一次定位，不后台追踪 |
| 重叠场次签到 | 同场同时段重叠时，已报名者签入其报名场次，空降者默认签入最新开球场次 |
| 记鸽权限 | 任何人不能手动记鸽（只有系统结算能产鸽）；发起人只有撤销权，撤销必须留痕 |
| 守约率展示 | 确定报名不足 5 场显示「新人」，不显示百分比 |

规则的唯一实现在 `miniprogram/utils/rules.js`，页面和数据层都只调用它，不复制数值。

## 第二阶段：微信云开发（已弃用，历史记录）

> 本节与 `cloudfunctions/`、`database/` 均为已弃用方案：微信云开发体验期后最低 19.9 元/月，不符合「免费后端」的要求，已整体被下方 uniCloud 方案替代。内容保留只读，供追溯规则口径的来历（uniCloud 版业务逻辑正是从这套 service/settle 迁移的，口径一字未变），**不要再按本节的部署清单操作**。

已交付的云端实现，要点如下：

- **api 云函数**：承接 store 全部方法签名（listGames / getGameDetail / createGame / signup / cancelSignup / checkin / getUserProfile），另提供发起人动作 updateGame / cancelGame / endGame / proxyCheckin 与申诉动作 submitAppeal / listAppeals / resolveAppeal / revokePigeon。用户身份只取云函数上下文的 **OPENID**，前端传的 user_id 不作身份；合并查重查全库在服务端做；签到围栏用上报经纬度与球局坐标在服务端复算，不信前端布尔值；改时间/地点在签到开启后锁定。
- **settle 云函数**：定时触发器每 5 分钟扫描到期球局（开球 +4 小时），调用与小程序端完全相同的 `rules.settleGame` 记鸽 / 守约进度 / 抵消。三重幂等：球局 `settled` 标记 + 鸽记录 `gameId+userId` 唯一键 + 每条报名/签到落账标记，连跑或中途失败重跑都不重复记账。
- **安全红线**：api 不提供任何手动记鸽入口，鸽只能由 settle 产生；发起人只有撤销权，代签与撤销都写留痕字段（操作者、时间、原因）；云数据库六个集合权限统一设为所有用户不可读写，只走云函数。
- **规则单一口径**：云端两份 `rules.js` 是 `miniprogram/utils/rules.js` 的逐字副本，同步规矩见 `cloudfunctions/SHARED_RULES.md`，测试里有字节级一致性用例守着。

## 后端迁移：uniCloud 免费方案（现行）

### 为什么迁、迁到哪

- 免费空间只有阿里云与支付宝云各提供 1 个（腾讯云无免费空间），本项目选**支付宝云免费空间**。
- 小程序端与 uniCloud 之间走**云函数 URL 化 HTTPS 接口**：请求合法域名填 uniCloud 提供的 `{spaceId}.api-hz.cloudbasefunction.cn`，**不需要自有域名、不需要为接口域名做备案**（小程序本身的备案照常办，那是另一回事）。
- 免费 ≠ 无限：**免费空间有效期只有 1 个月，到期前 15 天起可以续期，忘了续会被停服、数据会被释放**。这是免费方案最大的风险点，应对写在文末配合清单第 2 项（日历提醒 + 定期导出备份），务必照做。

### 架构（全部在 `uniCloud/`）

- **只有一个云函数 `api`**，三用：① URL 化 HTTPS 入口，内部按 `action` 路由（与 store 方法同名）；② `config.json` 的 timer 触发器**每小时**跑一次 settle 全量扫描；③ **惰性结算**：api 读到已过结算时刻（开球 +4 小时）且未结算的球局时，先对该局结算再返回，复用同一 `settleService` 与幂等口径。settle 不再是独立云函数，规则副本也因此只剩这一份（源头 + 三份副本的同步规矩见 `cloudfunctions/SHARED_RULES.md`）。
- **鉴权自建会话**（`auth.js`）：URL 化接口是公开 HTTP，没有上下文 OPENID。流程：小程序 `wx.login` 的 code → api 的 `login` action 转发微信 code2session（AppID/AppSecret 只配在云函数环境变量里，见 `uniCloud/cloudfunctions/api/config.js`）→ 换到 openid → 签发不透明随机 token 存 `sessions` 集合（30 天过期）→ 其余 action 一律校验 token，失败统一 `{ ok:false, error:'unauthorized' }`。小程序端 store 自动完成登录、缓存 token、失效自动重登一次并重试，页面无感知。
- **数据库 8 集合**（`uniCloud/database/`）：原六集合字段口径不变，新增 `sessions`（会话）与 `notifications`（通知落库，settle 落鸽/抵消时写入）。权限口径不变：schema 里四项权限全 `false` 挡客户端直连，只走云函数。
- **业务口径零变化**：service/settleService 由弃用版逐文件迁移，合并查重、围栏服务端复算、发起人权限、撤销留痕、结算三重幂等等全部原样；api 无手动记鸽入口的红线不变。另外补齐了弃用版 api 缺的四个读路由（`listPigeonRecords`、`getAppealContext`、`listMyGames`、`listNotifications`），与 mock 出参对齐。

### 配额预算（支付宝云免费空间，为什么够用）

免费配额：云函数调用 1.5 万次/月、资源用量 1000 GBs/月、出网流量 1 GB/月；DB 读 62 万 RU/月、写 31 万 WU/月、容量 6.2 GB·天。按下表假设估算（400 人群、日均 2 场、每场约 15 名参与者）：

| 消耗项 | 估算 | 月量 | 配额 | 说明 |
|---|---|---|---|---|
| 定时结算 | 每小时 1 次 | ≈720 次 | 调用 1.5 万/月 | 若按弃用版每 5 分钟跑，光定时器就 ≈8640 次/月，占掉一半多——这是把触发改每小时 + 惰性结算的主要原因 |
| 用户调用 | 每场约 90 次（报名/签到/刷详情等）×2 场/天 | ≈5400 次 | 同上 | 详情页刷新是主要消耗，别做高频轮询即可 |
| 机动（发起人裁决、联调、异常重试） | — | ≈1000 次 | 同上 | 合计 ≈7100 次，约占配额一半 |
| 函数资源 | 单次约 128MB×0.3s ≈ 0.04 GBs | ≈300 GBs | 1000 GBs/月 | 余量充足 |
| DB 读 | 详情一屏约读 40 条文档，日均约 200 屏 | ≈24 万 RU | 62 万 RU/月 | enrich 时按场拉报名/签到名单，是读大头但够用 |
| DB 写 | 报名/签到/结算落账，日均数百条 | ≈1–2 万 WU | 31 万 WU/月 | 余量充足 |
| 出网流量 | 响应均为小 JSON + code2session | 远低于 1 GB | 1 GB/月 | 本项目基本不用云存储 |

结论：当前规模下免费配额够用且有约一倍余量；真涨到不够时，先砍详情页刷新频率与列表数据量，再考虑付费，而不是先换架构。

### 部署要点（细节看文末 uniCloud 版配合清单）

开通免费空间 → 上传 `uniCloud/`（HBuilderX 或 uniCloud 控制台）→ 建 8 个集合与索引（或导入 `.schema.json` 与 `init_data.json`）→ 对 `api` 函数开启 URL 化、确认每小时 timer 触发器已随 `config.json` 生效 → 云函数环境变量配 `WX_APPID`/`WX_APP_SECRET` → 小程序端把空间域名加进 request 合法域名、把函数地址填进 `store.js` 的 `UNICLOUD_API_URL` 并把 `BACKEND` 改为 `'unicloud'`。

## 需要用户配合的事项清单（uniCloud 版）

以下事项只能由账号主体本人操作，代码侧均已留好占位。带 🔑 的值涉及密钥，**不要发到聊天里**，按说明直接填到云端配置。

1. **真实 AppID + AppSecret** 🔑
   - 做什么：注册小程序账号，拿到 AppID 与 AppSecret。
   - 在哪做：微信公众平台（mp.weixin.qq.com）→ 注册 → 小程序；AppID 在「开发管理 → 开发设置」，AppSecret 在同一页生成/重置（只显示一次，妥善保存）。
   - 填到哪：AppID 替换 `project.config.json` 里的 `touristappid` 占位（一行，可自己改也可发我）；**AppSecret 只填 uniCloud 云函数环境变量**：uniCloud 控制台/HBuilderX → 云函数 `api` → 环境变量，键名 `WX_APPID`、`WX_APP_SECRET`（读取位置在 `uniCloud/cloudfunctions/api/config.js`）。AppSecret 绝不能进小程序端代码、不能发聊天。
2. **注册 DCloud 账号、开通支付宝云免费空间** ⚠️ 带续期风险
   - 做什么：注册 DCloud 账号，新建一个**支付宝云免费服务空间**（免费空间阿里云/支付宝云各只有 1 个名额，别建错云厂商），上传 `uniCloud/` 并部署 `api` 云函数、对 `api` 开启 URL 化、确认每小时 timer 触发器（`settleTimerHourly`）已启用；按 `uniCloud/database/SCHEMA.md` 建 8 个集合与索引（可直接用目录里的 `*.schema.json` 与 `*.init_data.json`）。
   - 在哪做：uniCloud 控制台（unicloud.dcloud.net.cn）或 HBuilderX 的 uniCloud 面板。
   - ⚠️ **续期提醒（最重要）**：免费空间有效期 **1 个月**，到期前 15 天起可续期；**不续会被停服、空间与数据会被释放**。开通当天就做两件事：① 在手机日历建一个每月重复提醒（比如每月开通日提前 10 天）专门续期；② 养成定期在控制台**导出数据库备份**的习惯（建议每月续期时顺手导一次），万一漏续也有数据可恢复。
   - 做完发回：把**服务空间 ID（spaceId）** 和 **api 函数的 URL 化地址**（形如 `https://{spaceId}.api-hz.cloudbasefunction.cn/api`）发我，我填进 `miniprogram/utils/store.js` 的 `UNICLOUD_API_URL` 并把 `BACKEND` 切到 `'unicloud'` 联调。
3. **request 合法域名**
   - 做什么：把 uniCloud 提供的域名 `{spaceId}.api-hz.cloudbasefunction.cn` 加入小程序 request 合法域名（只填域名，不带 `https://` 和路径）。不加这一步，真机上所有请求会被微信拦截（开发者工具勾选「不校验合法域名」只能本地调试用）。
   - 在哪做：微信公众平台 → 开发管理 → 开发设置 → 服务器域名 → request 合法域名。
   - 做完发回：告诉我已添加即可，不用发截图。
4. **订阅消息模板申请**
   - 做什么：为四类通知各选/申请一个订阅消息模板：球局变更、签到开启提醒、结算结果、成局里程碑。模板字段尽量选含「时间、地点、人数」语义的现成模板，类目不符时走申请新模板。
   - 在哪做：微信公众平台 → 功能 → 订阅消息 → 公共模板库。
   - 做完发回：把 4 个**模板 ID** 发我，我填入 `miniprogram/app.js` 顶部的 `SUBSCRIBE_TEMPLATE_IDS`（已按四类留空占位，键名一一对应）。注意：模板没到位不影响其他功能上线，只是订阅消息发不出去，站内通知（notifications 集合）与落地页已就绪。
5. **真机定位验证**
   - 做什么：部署后用真机到任意一个球场围栏内/外各签到一次，确认定位权限弹窗、围栏 500 米判定、弱信号下的表现；再在开发者工具模拟器里改定位复测一次距离不足跳结果页的文案。
   - 在哪做：真机预览（开发者工具扫码）+ 实地图方便即可，不必真去球场，围栏外样本在小区/公司就能测。
   - 做完发回：告诉我机型、系统版本与实测距离误差大概多少米；误差普遍偏大时我们再调围栏半径口径。
6. **小程序类目与提审**
   - 做什么：确认类目（约球/体育类工具，避开需额外资质的类目）、补齐隐私保护指引（定位用途已在 app.json 声明）、用户协议与隐私政策文本，最后提交审核并发布。
   - 在哪做：微信公众平台 → 设置 → 基本设置/类目；版本管理 → 提交审核。
   - 做完发回：把类目审核或版本审核的结果（通过/被驳回原因）发我；被驳回把原文发我，我按原因改代码或文案再提。
